WHAT THIS PROBE DOES NOT MEASURE - read before quoting any number above

  1. It is not a fine-tune. It measures one operation family in isolation.
  2. The fraction of a real QLoRA training step spent in FrozenQuantizedLinear has NEVER
     been measured in this project. Nothing decomposes the step. So a speedup here does
     NOT convert into an end-to-end fine-tune speedup, in either direction. This project
     has already measured one kernel benchmark under-reporting a real end-to-end effect
     by 4.3x, so the gap is not a small correction.
  3. No dequantize runs on the device. The device arms receive an F32 weight. A real port
     must either dequantize Q4_K/Q6_K on the device or upload F32 - and the F32 Qwen-3B
     base is about 11.5 GB, which does not fit most consumer cards. The probe says nothing
     about how fast a device-side Q4_K dequantize would be.
  4. FP32 CUDA cores only. ILGPU has no tensor-core path. On a modern NVIDIA card the
     BF16/TF32 tensor rate is roughly an order of magnitude above the FP32 rate, so this
     is the FLOOR of what the hardware can do, not its ceiling.
  5. No optimizer, no LoRA adapter operations, no autograd tape overhead, no host-device
     traffic inside a step, no multi-GPU.
  6. It measures OUR kernels, not the card. Arm X1 exists so that, when the CUDA toolkit
     is present, the gap between our kernel and cuBLAS is a number rather than a guess.
  7. Arm C4 is not in the signed plan's arm table. It was added so the device backward has
     a CPU counterpart that performs the same work; arm C2 includes a dequantize that G3
     never runs.
